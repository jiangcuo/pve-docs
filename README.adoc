= Proxmox VE 文档

我们致力于为 {website}[{pve}] 生成高质量文档，并选择
http://www.methods.co.nz/asciidoc/[AsciiDoc] 作为基础格式。

基本思路是生成高质量手册页，并将它们组合成一本完整书籍，即
link:pve-admin-guide.adoc[Proxmox VE Administration Guide]。这样只需维护一份
源文件，就能从中生成多种文档。也可以生成可打印的 PDF 文件，或电子书格式
（'.epub'）。

在可能的情况下，我们提供脚本从源代码中提取 API 定义、配置或命令行选项。

为简化文档工作，我们将所有文档保存在此仓库中。无需安装任何额外 Proxmox 软件包，
即可使用以下命令生成文档：

 make pve-doc-generator.mk
 make index

要更新自动生成的 API 定义，请使用：

 make update

NOTE: 这需要完整安装的开发环境。

.常用命令示例
----
make pve-doc-generator.mk
make index
make deb
----

== Debian 软件包

我们会生成名为 'pve-doc-generator' 的开发软件包，其他 Proxmox VE 软件包会在
构建时使用它生成手册页。

另一个名为 'pve-docs' 的软件包用于在我们的 Web 服务器上发布生成的 '.html' 和
'.pdf' 文件。可以使用以下命令生成这些 Debian 软件包：

 make deb


== link:asciidoc/asciidoc-pve.conf[] 中的通用宏定义

'asciidoc' 允许我们定义通用宏，随后可使用 `{macro}` 引用这些宏。我们尝试通过
该机制提升一致性。例如，我们定义了名为 `pve` 的宏，它会展开为 "Proxmox VE"。

对于使用多次的 URL，应定义两个宏：

* `{name-url}`，只包含 http(s) URL
* `{name}`，包含完整链接以及规范描述

例如，宏 `{forum-url}` 会展开为 {forum-url}，宏 `{forum}` 会展开为 {forum}。

计划是为使用多次的术语添加更多此类定义。

WARNING: 当 asciidoc 遇到拼写错误的宏名称时，会静默丢弃包含该宏的整行！


== 自动生成的 CLI 命令概要

我们会自动生成所有手册页的命令行概要。之所以能做到这一点，是因为我们拥有
{pve} API 的完整声明式定义。我已将这些生成文件（'*-synopsis.adoc'）加入 git
仓库，这样即使没有完整安装的 {pve} 开发环境，也可以构建文档。

== 风格指南

'asciidoc' 使用相当简单的标记语法来格式化内容。整个文档中应遵循以下基本原则。


=== 章节

章节使用 `two-line titles' 格式：在标题文本下方添加一行合适字符，长度与章节标题
相同：

 Level 0 (top level):     ======================
 Level 1:                 ----------------------
 Level 2:                 ~~~~~~~~~~~~~~~~~~~~~~
 Level 3:                 ^^^^^^^^^^^^^^^^^^^^^^
 Level 4 (bottom level):  ++++++++++++++++++++++

NOTE: 4 级标题目前无法用于 `manpage` 输出。可以改用 `.SECTION'，它会得到相同的
渲染效果；并且该级别标题无论如何都不会显示在任何 Index/TOC 中。

章节标题前应始终有两个空行。标题中的每个词都应首字母大写，但``冠词、并列连词、
介词，以及不定式中的 to 除外，除非它们出现在标题开头或末尾''（参见
http://web.mit.edu/course/21/21.guide/capitals.htm[Mayfield Electronic Handbook of Technical & Scientific Writing]）。


=== 列表

==== 编号列表

编号列表应使用隐式编号格式创建：

-----
. First level
.. Second level
. First level again
-----

. First level
.. Second level
. First level again


==== 项目符号列表

项目符号列表应使用 '*' 符号创建：

-----
* First level
** Second level
* First level again
-----

* First level
** Second level
* First level again


如果需要让其他元素与某个列表项处于同一级别，可以使用 '+' 符号：

----
. 第一层
.. 第二层
+
同一第二层上的另一个句子（或块）。
. 再次回到第一层
----

. 第一层
.. 第二层
+
同一第二层上的另一个句子（或块）。

. 再次回到第一层

==== 标签列表

标签列表应用于提升键值样式文本列表的可读性，例如命令行参数或配置选项：

.常规标签列表
-----
第一个标签文本::

元素文本段落

第二个标签文本::

另一个元素文本段落。
-----

第一个标签文本::

元素文本段落

第二个标签文本::

另一个元素文本段落。

.水平标签列表
-----
[horizontal]
第一个标签文本:: 元素文本段落

第二个标签文本:: 另一个元素文本段落。
-----

生成

[horizontal]
第一个标签文本:: 元素文本段落

第二个标签文本:: 另一个元素文本段落。

FAQ 章节对标签列表使用特殊的问答样式。


=== 文本和块样式

'asciidoc' 提供多种默认文本样式：

* 'Emphasized text'：使用 \'text' 创建，用于强调单词和短语
* `Monospaced text`：使用 \`text` 创建，用于命令/程序名、文件路径、行内命令、
选项名称和值
* *Strong text*：使用 \*text* 创建，用于在章节首次引入概念或名称时进行强调。

文档中还使用了不同的内置块样式：

可以通过在每行前添加空白字符来按字面量包含完整段落。可用它来格式化独占一行的
完整命令，例如：

 pct set ID -option value

----
用至少四个 '-' 字符组成的行包围段落时，其内容会格式化为 listing。

可用它格式化文件内容或命令输出。
----

特殊高亮的 'tips'、'notes'、'warnings' 和 'important' 信息可以通过以 `TIP`、
`NOTE:`、`WARNING:` 或 `IMPORTANT:` 开头的段落创建：

TIP: 这是一条提示

NOTE: 这是一条说明

WARNING: 这是一条警告

IMPORTANT: 这是重要信息

对于这些块（包括列表和段落），可以通过在块前添加 `.' 字符和标题文本来定义块
标题：

-----
.列表标题
* 第一个元素
* 第二个元素
* 第三个元素
-----

.列表标题
* 第一个元素
* 第二个元素
* 第三个元素

例如，可以使用块标题为文件内容 listing 添加文件名/路径。


== 在线帮助
每个 {pve} 安装都包含 HTML 格式的完整文档，并将其作为 GUI 中各种帮助按钮的
目标。

如果在文档中添加特定条目后，希望创建指向该条目的帮助按钮，需要执行以下操作：

* 在文档条目前添加双中括号形式的字符串 id，例如 `[[qm_general_settings]]`
* 重新构建 `asciidoc-pve` 脚本以及包含该条目的 HTML 章节文件
* 在要编写文档的 ExtJS 面板中添加属性 `onlineHelp`，使用上述字符串，例如
`onlineHelp: qm_general_settings`
该面板必须是 PVE.panel.InputPanel 的子类

调用 `make install` 时，asciidoc-pve 脚本会填充一个 JS 对象，将字符串 id 与本地
HTML 文档链接关联起来；输入面板的帮助按钮会指向该链接。


== 截图

[thumbnail="screenshot/gui-datacenter-search.png"]

首先需要注意，我们可以在 'html' 和 'wiki' 页面显示截图，也可以将它们包含在
打印文档中。但无法在手册页内渲染截图。因此，手册页中的截图应是可选的，也就是
正文不应依赖截图可见。可以通过在段落上设置 'thumbnail' 属性来包含截图：

----
[thumbnail="screenshot/gui-datacenter-search.png"]
首先需要注意 ...
----

对应文件需要位于 `images/screenshot` 文件夹中，并应采用 `.png` 图像格式。我们会
在打印文档中包含截图，而 'pdftex' 会使用文件中指定的密度（DPI）。因此所有截图
应使用相同密度。当前要求密度设置为 146 DPI，以便显示 1024 像素宽的图像。不应
包含更大的截图（虽然技术上可以）。

可以使用 `./png-cleanup.pl` 脚本设置正确密度。只需使用以下命令导入截图图像：

----
# ./png-cleanup.pl screenshot.png images/screenshot/screenshot.png
----

TIP: 可以使用 `identify -verbose screenshot.png` 命令显示所有图像属性（来自
Debian 软件包 'imagemagick'）

.默认截图布局

[thumbnail="screenshot/gui-datacenter-search.png"]

通常会将截图作为小缩略图显示在段落右侧。在打印文档中，我们会在段落之前渲染
完整大小的图像；如果段落有标题，则渲染在标题和正文之间。通常建议为带截图的
段落添加标题。

[thumbnail="screenshot/gui-datacenter-search.png", float="left"]

如果需要渲染大量截图，也可以将其放在左侧，因此可以使用 `float` 属性交替缩略图
位置：

----
[thumbnail="screenshot/gui-datacenter-search.png", float="left"]
如果需要渲染大量截图 ...
----

请避免连续放置过多截图，以免产生渲染问题。还应验证打印文档，检查大截图是否会
造成布局问题。
