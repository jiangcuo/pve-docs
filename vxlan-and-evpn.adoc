=== 使用非 VLAN 感知 Linux 网桥的 VXLAN 二层网络

VXLAN 是一种覆盖网络，用于在现有 IP 网络之上传输以太网流量，同时支持数量非常大的
租户。它定义于 RFC 7348。每个覆盖网络称为一个 VXLAN Segment，并通过唯一的 24 位
段 ID 标识，该 ID 称为 VXLAN Network Identifier（VNI）。

VXLAN 封装会增加 50 字节开销，因此需要将主机物理接口的 MTU 至少提高到 1550
（或将虚拟机内部的 MTU 降低到 1450）。

对于 BUM 流量（广播/未知单播流量、多播），有 3 种不同的 VXLAN 设置模式：
multicast、unicast、bgp-evpn。

==== 常用命令示例

以下命令可用于在节点上只读检查 VXLAN 设备、网桥 FDB 与路由状态：

----
# ip -d link show type vxlan
# bridge fdb show
# ip route show
----

==== multicast 模式

此场景依赖头端复制，即终端主机在没有目标 MAC 地址条目时，会向 VXLAN 网络中的其他
设备/VTEP 发送 ARP。实现方式是将请求发送到 VXLAN 多播组，远端 VTEP 会接收该数据包，
并直接向发起请求的 VTEP 作出相应应答。


* node1

----
auto eno1
iface eno1 inet manual
	mtu 1550

auto vmbr0
iface vmbr0 inet static
        address 192.168.0.1
        netmask  255.255.255.0
        bridge_ports eno1
        bridge_stp off
        bridge_fd 0

auto vxlan2
iface vxlan2 inet manual
        vxlan-id 2
        vxlan-svcnodeip 225.20.1.1
        vxlan-physdev eno1

auto vmbr2
iface vmbr2 inet manual
        bridge_ports vxlan2
        bridge_stp off
        bridge_fd 0

auto vxlan3
iface vxlan3 inet manual
        vxlan-id 3

==== unicast 模式

可以通过将 BUM 帧头端复制到静态配置的远端 VTEP 列表来替代多播。此时定义 VXLAN 时
不使用远端多播组。相反，所有远端 VTEP 都会与全零地址关联：BUM 帧会被复制到所有
这些目标。VXLAN 设备仍会使用源地址学习自动学习远端地址。

* node1

----
auto eno1
iface eno1 inet manual
	mtu 1550

auto vmbr0
iface vmbr0 inet static
        address 192.168.0.1
        netmask  255.255.255.0
        bridge_ports eno1
        bridge_stp off
        bridge_fd 0


auto vxlan2
iface vxlan2 inet manual
        vxlan-id 2
        vxlan_remoteip 192.168.0.2
        vxlan_remoteip 192.168.0.3


auto vmbr2
iface vmbr2 inet manual
        bridge_ports vxlan2
        bridge_stp off
        bridge_fd 0


auto vxlan3
iface vxlan2 inet manual
        vxlan-id 3

        vxlan_remoteip 192.168.0.3

==== bgp-evpn

VTEP 通过 BGP 在控制平面学习/分发远端 MAC 地址，而不是使用数据平面学习。
VTEP 能够抑制 VXLAN 隧道上的 ARP 泛洪。

此处使用的控制平面是 FRR，即一种 BGP 路由软件。Proxmox 集群中的每个节点都与其他
节点建立对等关系。对于更大的网络或多个 Proxmox 集群，也可以使用外部 BGP 路由反射器
服务器。

* node1

----
auto eno1
iface eno1 inet manual
	mtu 1550

auto vmbr0
iface vmbr0 inet static
        address 192.168.0.1
        netmask 255.255.255.0
        bridge_ports eno1
        bridge_stp off
        bridge_fd 0

auto vxlan2
iface vxlan2 inet manual
        vxlan-id 2
        vxlan-local-tunnelip 192.168.0.1
        bridge-learning off
        bridge-arp-nd-suppress on
        bridge-unicast-flood off
        bridge-multicast-flood off


auto vmbr2
iface vmbr2 inet manual
        bridge_ports vxlan2
        bridge_stp off
        bridge_fd 0


auto vxlan3
iface vxlan3 inet manual
        vxlan-id 3
        vxlan-local-tunnelip 192.168.0.1
        bridge-learning off
        bridge-arp-nd-suppress on
        bridge-unicast-flood off
        bridge-multicast-flood off


auto vmbr3
iface vmbr3 inet manual
        bridge_ports vxlan3
        bridge_stp off
        bridge_fd 0
----


/etc/frr/frr.conf

----
router bgp 1234
 no bgp default ipv4-unicast
 coalesce-time 1000
 neighbor 192.168.0.2 remote-as 1234
 neighbor 192.168.0.3 remote-as 1234
 !
 address-family l2vpn evpn
  neighbor 192.168.0.2 activate
  neighbor 192.168.0.3 activate
  advertise-all-vni
 exit-address-family
!
line vty
!
----

=== 使用任播网关的 VXLAN 三层路由

在这种需求下，每个 vmbr 网桥都会作为虚拟机的网关。不同节点上的同一个 vmbr
会使用相同的 IP 地址和相同的 MAC 地址，以确保虚拟机在线迁移可正常工作且网络不中断。

VXLAN 三层路由只适用于 FRR 和非 VLAN 感知网桥。
（VLAN 感知网桥支持当前仍存在问题。）

==== 非对称模型

这是最简单的模式。要使其工作，所有 vxlan 都需要在所有节点上定义。

非对称模型允许在 VXLAN 隧道入口执行路由和桥接，但在出口只执行桥接。
因此，双向 VXLAN 流量在经过路由基础设施时，会在每个方向上使用不同的 VNI
（始终是目标 VNI）。

image::images/vxlan-l3-asymmetric.svg["vxlan l3 asymmetric",align="center"]

* node1

----
auto eno1
iface eno1 inet manual
	mtu 1550

auto vmbr0
iface vmbr0 inet static
         address 192.168.0.1
         netmask  255.255.255.0
         bridge_ports eno1
         bridge_stp off
         bridge_fd 0

auto vxlan2

        vxlan-id 2
        vxlan-local-tunnelip 192.168.0.1
        bridge-learning off
        bridge-arp-nd-suppress on
        bridge-unicast-flood off
        bridge-multicast-flood off

==== 对称模型

使用此模型时，不需要在所有节点上拥有全部 vxlan。将流量路由到外部路由器时也需要
使用此模型。

对称模型会在入口和出口叶节点上同时执行路由和桥接。因此，双向流量能够在同一个 VNI
上传输，这也是“对称”名称的由来。不过，所有经过路由的 VXLAN 流量都会使用一个新的
专用传输 VNI，称为 L3VNI。所有需要路由的流量都会被路由到 L3VNI，经由三层基础设施
隧道传输，再从 L3VNI 路由到合适的 VLAN，最终桥接到目标。

L3VNI 需要一个 vrf，因此如果所有 vmbr 网桥需要彼此可达，就必须都位于该 vrf 中。

image::images/vxlan-l3-symmetric.svg["vxlan l3 symmetric",align="center"]

* node1

----
auto vrf1
iface vrf1
    vrf-table auto

auto eno1
iface eno1 inet manual
	mtu 1550

auto vmbr0
iface vmbr0 inet static
         address 192.168.0.1
         netmask  255.255.255.0
         bridge_ports eno1
         bridge_stp off
         bridge_fd 0

auto vxlan2
iface vxlan2 inet manual
        vxlan-id 2
        vxlan-local-tunnelip 192.168.0.1
        bridge-learning off
        bridge-arp-nd-suppress on
        bridge-unicast-flood off
        bridge-multicast-flood off

auto vmbr2
iface vmbr2 inet static
        bridge_ports vxlan2
        bridge_stp off
        bridge_fd 0
        address 10.0.2.254
        netmask 255.255.255.0
        hwaddress 44:39:39:FF:40:94 #must be same on each node vmbr2
        vrf vrf1
        ip-forward on
        ip6-forward on
        arp-accept on

auto vxlan3
iface vxlan3 inet manual
        vxlan-id 3
        vxlan-local-tunnelip 192.168.0.1
        bridge-learning off
        bridge-arp-nd-suppress on
        bridge-unicast-flood off
        bridge-multicast-flood off

auto vmbr3

        bridge_ports vxlan3
        bridge_stp off
        bridge_fd 0
        address 10.0.3.254
        netmask 255.255.255.0
        hwaddress 44:39:39:FF:40:94 #must be same on each node vmbr3
        vrf vrf1
        ip-forward on
        ip6-forward on
        arp-accept on

auto vxlan4000

        bridge-learning off
        bridge-arp-nd-suppress on
        bridge-unicast-flood off
        bridge-multicast-flood off

        bridge_fd 0

==== 多个网关节点
在此示例中，所有节点都会作为出口网关使用（如果需要，也可以只使用 2 个节点）。
所有节点都有一个指向外部路由器（192.168.0.254）的默认网关（路由器和 node1
之间没有 BGP），并在 vrf 中通告该默认网关（default originate）。外部路由器拥有
到所有 Proxmox 节点的 ECMP 路由（用于负载均衡）。如果路由器将数据包发送到错误节点
（虚拟机不在该节点上），该节点会通过 vxlan 将数据包路由到最终目标。

如果有多个网关节点，请禁用 rp_filter，因为数据包可能从一个节点进入，并从另一个节点
发出。

sysctl.conf 调优
-----
net.ipv4.conf.default.rp_filter=0
net.ipv4.conf.all.rp_filter=0
-----

==== 说明

如果外部路由器不支持通过 `ECMP static routes` 到达多个 {pve} 节点，可以使用
Virtual Router Redundancy Protocol（VRRP）在 Proxmox 节点上设置 HA 浮动 VIP。

在此示例中，会在 node1 和 node2 上设置一个浮动 IP 192.168.0.10。node1 为主节点，
发生故障时故障转移到 node2。

此设置当前需要 `vrrpd` 软件包（`apt install vrrpd`）。
#TODO : 使用最新版本时，应该可以直接通过 FRR 实现。

----
auto vmbr0

         address 192.168.0.1
         netmask  255.255.255.0
         gateway 192.168.0.254
         bridge_ports eno1
         bridge_stp off
         bridge_fd 0
         vrrp-id 1
         vrrp-priority 1
         vrrp-virtual-ip 192.168.0.10
----

auto vmbr0

         address 192.168.0.2

         bridge_stp off
         bridge_fd 0

         vrrp-priority 2
         vrrp-virtual-ip 192.168.0.10

==== 路由反射器
如果有大量 Proxmox 节点或多个 Proxmox 集群，可能希望避免所有节点彼此建立对等关系。
为此，可以创建专用的 route reflector（RR）服务器。由于单个 RR 是单点故障，强烈建议
至少使用两台服务器作为 RR，以实现冗余。

以下是使用 `frr` 的配置示例，其中包含 `rrserver1 (192.168.0.200)` 和
`rrserver2 (192.168.0.201)`。

rrserver1
----
router bgp 1234
  bgp router-id 192.168.0.200
  bgp cluster-id 1.1.1.1  #cluster-id must be the same on each route reflector
  bgp log-neighbor-changes
  no bgp default ipv4-unicast
  neighbor fabric peer-group
  neighbor fabric remote-as 1234
  neighbor fabric capability extended-nexthop
  neighbor fabric update-source 192.168.0.200
  bgp listen range 192.168.0.0/24 peer-group fabric #allow any proxmoxnode client in the network range
  !
  address-family l2vpn evpn
   neighbor fabric activate
   neighbor fabric route-reflector-client
   neighbor fabric allowas-in
  exit-address-family
  !
  exit
!
----

rrserver2
----
router bgp 1234
  bgp router-id 192.168.0.201
  bgp cluster-id 1.1.1.1
  bgp log-neighbor-changes
  no bgp default ipv4-unicast
  neighbor fabric peer-group
  neighbor fabric remote-as 1234
  neighbor fabric capability extended-nexthop
  neighbor fabric update-source 192.168.0.201
  bgp listen range 192.168.0.0/24 peer-group fabric
  !
  address-family l2vpn evpn
   neighbor fabric activate
   neighbor fabric route-reflector-client
   neighbor fabric allowas-in
  exit-address-family
  !
  exit
!
----
